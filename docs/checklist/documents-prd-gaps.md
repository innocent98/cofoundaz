## Works (verified live)
- ✅ **Real API everywhere:** the library, editor, templates, signatures, shared and both public pages all call the real API. The only static
  data is dead code (gap 35).
- ✅ **Writes are role-gated at the API:** mentor and consultant get `403 FORBIDDEN` "You don't have permission to do that." on create, edit,
  delete, share, upload and signature request. A wrong `X-Workspace-Id` is `403`, a missing token `401`. Edit-level share (`access_level: edit`) is a
  `422`, as the guide says.
- ✅ **Upload:** file chosen through the real input lands in the list ("All documents" went 6 to 7); the folder form field is honoured; over
  15 MB returns `422 "File must be 15 MB or smaller."`; `.md` returns `422 "That file type isn't allowed..."`.
- ✅ **Editor:** edit and **Save** (version 1 to 2), and a stale save while another writer bumped the version shows the "Reload latest"
  banner (the `409 DOCUMENT_VERSION_CONFLICT` path), then saves after reload.
- ✅ **Share:** Share modal creates a link shown once with **Copy**; the public `/shared/{token}` page renders the document read-only
  with "View Only" and the expiry date; revoke makes the token 404 (API).
- ✅ **E-sign:** two-signer request created from the UI; the signer page shows the file, a typed-name field with a script preview, the consent
  checkbox ("I agree that typing my name above is my electronic signature...") which gates **Sign document**; first signature shows "1 of 2 signed";
  the second completes the request (`status: complete`, `signed_count: 2`); a used link is a uniform `404`; **Remind** returns `{"reminded":1}`;
  **Cancel** works and a second cancel is `409 SIGNATURE_NOT_ACTIVE`. The page carries a legal caveat line.
- ✅ **Notifications fire** on share, request, signed and completed (but see gap 4 for who gets them).
- ✅ **375:** no page-level horizontal scroll on any Documents page (the clipping inside cards is gap 29 and 30).

## Decisions needed (proposed defaults; none block the BE security slice)
1. **Q1, what is "Shared with me" for mentors, advisors, investors and accountants?** Today a share is an anonymous token link. The PRD gives
   M / LA / INV / AC accounts per-document access plus a landing list with Can view / comment / edit. Default: add account-bound grants (by user or
   email) on top of the token link, view and comment first, edit later (needs a doc-level concurrency story).
2. **Q2, e-signature level:** keep simple typed-name signatures (plus stamped PDF and certificate, field placement) or integrate a
   certificate-based provider (the PRD service table says "e-sign provider")? Default: simple signatures now with the legal caveat, provider later.
3. **Q3, upload limit and storage:** PRD says 100 MB, the API enforces 15 MB (Cloudinary-friendly). Default: stay at 15 MB for MVP, say so in the UI, and
   revisit with object storage (S3) when large decks and data-room files matter.
4. **Q4, legal templates:** who supplies counsel-reviewed text (NDA, contractor, founder agreement, SAFE) and which disclaimer ships with them?
   Default: ship five structured drafts with a clear "not legal advice" banner and let a lawyer replace the text later.
