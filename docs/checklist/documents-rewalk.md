**Date:** 2026-10-25, re-checked 2026-10-27 and 2026-10-29. **Verdict: ✅ (2026-10-29).** D1 to D4 and D6 to D8 are fixed and every control passes on merged develop at 1440 and 375 (see Third pass and Fourth pass); D5 is a Funding dependency outside Documents. Original first-pass result: 93 of 103 recorded checks pass, 8 are ❌ (D1 to D8; all Low to Med, no data or permission leak), 1 is unit-tested only and 1 is env-only (staging CORS). The security and e-sign paths that were the big risks all passed live (role gating, grants, link shares, sequential signing, executed PDF, certificate, notifications audience). Documents becomes ✅ once D1 to D3, D6 to D8 are fixed and re-checked (D4 is outside Documents, D5 is a Funding dependency).

**What was walked.** Merged `origin/develop` `3395635` (FE #174 merge) in my own `next dev` on `:3911`, proxied to the shared local API on `:8000` (develop `ccb30cf9`, migration `0076`, api and worker sharing `app_storage`). Hosts keep logins apart: `localhost` (founder), `tm.localhost`, `m.localhost`, `bc.localhost`, `acc.localhost` (accountant), `inv.localhost` (investor), `pub.localhost`/`sign.localhost`/`sign2.localhost` (anonymous public pages).

Their passwords were chosen locally and are not recorded here. **The investor could not be made through the app's invite flow** (D5): I signed the account up, invited it as accountant, accepted, then changed `memberships.role` to `investor` directly in the local dev DB. That is the only direct DB write.

**How it was driven.** Hand clicks in the built-in browser pane at 1440x900 and 375x812 (emulated). Three honest limits: (1) the pane has no file picker, so uploads went through the page's real `<input type=file>` with a File object I built in JS; (2) the pane denies clipboard access, so "Copy link" could only show its fallback (D1); (3) typing into `<input type=date>` does not register in this pane, so date fields were set with the form-fill tool (the app's own save handler then ran normally). A second pass (same branch) hand-clicked every menu, modal and drawer at 375x812 with refs plus a script that measured each overlay (left/right edge, clipped controls, target size); this is what found D6 to D8, which the first layout-only pass missed.

**Test data.** Rows created by this walk are in the local NovaPay workspace (documents "Rewalk ...", exports, one signed request `ac9ba09f`, several cancelled requests, folder "Rewalk Folder", one "Walk NDA BE-D" doc renamed "Rewalk Doc A").
