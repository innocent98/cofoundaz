# Documents: hand re-walk (merged develop)

**Date:** 2026-10-25. **Verdict: not ✅ yet.** 76 of 87 recorded checks pass, 5 are ❌ (all Low to Med, none a data or permission leak) and 6 could not be verified. The security and e-sign paths that were the big risks (role gating, grants, link shares, sequential signing, executed PDF, certificate) all passed live. Documents becomes ✅ once D1 to D4 are fixed and the open hand-clicks below are done.

**What was walked.** Merged `origin/develop` `3395635` (FE #174 merge) in my own `next dev` on `:3911`, proxied to the shared local API on `:8000` (develop `ccb30cf9`, migration `0076`, api and worker sharing `app_storage`). Workspace NovaPay. Every result was compared with the raw API response (curl with a bearer token and `X-Workspace-Id`). Emails were read from the `[email:console]` lines in the api and worker logs. Hosts keep logins apart: `localhost` (founder), `tm.localhost`, `m.localhost`, `bc.localhost`, `acc.localhost` (accountant), `inv.localhost` (investor), `pub.localhost`/`sign.localhost`/`sign2.localhost` (anonymous public pages).

**Accounts (local only, never committed).** `throwaway-founder`, `rewalk-tm`, `bb-mentor-1`, `bb-consultant-1` @example.com (the shared test password). New for this walk: `rewalk-accountant@example.com` (created through the real invite flow: team invite email, signup, email verify, accept invite, on the UI) and `rewalk-investor@example.com`. Their passwords were chosen locally and are not recorded here. **The investor could not be made through the app's invite flow** (D5): I signed the account up, invited it as accountant, accepted, then changed `memberships.role` to `investor` directly in the local dev DB. That is the only direct DB write.

**How it was driven.** Hand clicks in the built-in browser pane at 1440x900 and 375x812 (emulated). Three honest limits: (1) the pane has no file picker, so uploads went through the page's real `<input type=file>` with a File object I built in JS; (2) the pane denies clipboard access, so "Copy link" could only show its fallback (D1); (3) typing into `<input type=date>` does not register in this pane, so date fields were set with the form-fill tool (the app's own save handler then ran normally). The 375 pass audited layout by script plus screenshots on the main pages; menus and modals were not each clicked at 375 (see "Not verified").

**Test data.** Rows created by this walk are in the local NovaPay workspace (documents "Rewalk ...", exports, one signed request `ac9ba09f`, several cancelled requests, folder "Rewalk Folder", one "Walk NDA BE-D" doc renamed "Rewalk Doc A"). Nothing was sent to a real address: every recipient is `@example.com`.
